# Portable board: dependency and path audit

The vendored source is the original `goals.ts`, RPM parser/editor, project list and project page, docs page and library from the supplied board snapshot. The existing `/board/projects` view is the default in that snapshot; `/board` now serves it directly. The list and project page retain their original dark palette, type fallbacks, progress bars and plan columns. The server and CLI have been reduced to a local, dependency-free starter. No private demo fixtures, machine scripts, lockfiles, package dependencies or personal data from the board repository are shipped.

## Optional server modules not included

The original server imported substantially more than a project board. The following dependencies and paths are removed with their modules, not replaced by invented local services:

- `board.ts`, `domain/fsreader.ts`, `tracker.ts`, `truth-check.ts`, `shelf-reader.ts`, `keeper-health.ts`, `disk-status.ts`, `waker.ts`, `pickup.ts`, `restarter.ts`, `restart-log.ts`, `ray-controls.ts`, `ray-launcher.ts`: original tracker and shelf files, fleet truth/process scans, Windows process tools (`powershell.exe`, `pwsh`, `taskkill`), restarter state/logs under `~/.ray-restarts`, desktop automation, hard-coded Rays defaults and keeper wake paths. No external state is inferred.
- `sources/transcripts.ts`, `session-chat.ts`, `chat-send.ts`, `chat-ask.ts`: `~/.claude/projects`, `~/.claude/sessions`, `CLAUDE_PROJECTS_DIR`, `CLAUDE_SESSIONS_DIR`, Claude local messaging sockets, transcript fixtures, chat ask/proxy endpoints. The portable board does not read transcripts or send chat messages.
- `project-arpe.ts`, `handoff-detail.ts`, `handoff-results.ts`, `handoff-panel-api.ts`, `handoffs-page.ts`, `jobs-page.ts`, `reply-diffs.ts`, `ledger-reader.ts`, `open-handoff.ts`, `sources/handoffs.ts`: `.docs/chatgpt/small` and prompt/queue/keeper logs, `chatgpt-bridge/files/keeper.ts` under Code root, ledger, reply-diff jobs, browser conversation opening, rescue/retry/fleet settings. Handoff folders are scaffolded for manual use, not registered with a keeper.
- `sources/open-with.ts`, `diff-view.ts`, `diff-page.ts`, `git-reader.ts`, `commit-match.ts`: `md-aio`, `RAY_BOARD_RENDER_LIBS`, sibling `md-aio/public/vendor/libs.js`, external browser/viewer and git diff commands. Docs are rendered as safe text using the existing document panel; no external renderer or font download. The fixed owner manifesto path under `toolset/docs/manifesto/book` has also been removed.
- `sources/usage-proxy.ts`, `sources/codex-gate.ts`, `domain/codex-*`, `surfaces/*`, `PROXY_ORIGIN`, upstream proxy/chat endpoints, Codex budget/caller configuration, `zod` and MCP/CLI surfaces: not needed for the starter; omitted. No remote API calls from the board.
- `goal-write.ts`, `ray-goals-api.ts`, `projects-api.ts`, `decisions.ts`, `decision-notifications.ts`, `checks.ts`: mutation, automatic checks, notifications and decision inbox APIs omitted. The read-only view shows the original RPM card fields, plain Markdown decision/insight notes, and declared Check. Unsupported controls are hidden. The original Node check runner and Diamond plugin remain in the repository for the original workflow.

The plain background runner intentionally has no watchdog or boot persistence. `ray board` and `ray restore` start it again if it is down. `ray new` creates files without launching an agent, so it works on a stranger's computer before any account setup. The original CLI's Windows workspace allocation, implicit trust, implicit Git commits and fleet restart side effects are intentionally not reproduced. The original static-site installer remains available through `--legacy` / `-Legacy` so its screenshots, check runner and intentionally broken-link example continue to work separately.

The `rpm-check.ts` logic is the supplied checker; the only change is its main-entry guard so the explicit Node fallback can execute it. The weekly review date is generated at creation, not frozen in a template. Its PASS is structural validation, not proof that a mission or its outcome check has passed.
