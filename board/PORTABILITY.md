# Portable board

The starter installs the vendored TypeScript board and `ray` command with Bun (or the explicit Node fallback). It uses one managed configuration in `~/.arpe/settings.json`, including `root`, `port`, optional `sharePort`, `shareOrigin`, `claudeProjectsDir`, and `usageProxyDb`. There are no checkout-specific defaults or dependencies on an external process supervisor. The owner board binds to localhost; a configured sharing listener binds separately to IPv4 loopback. Only the company router runs on that listener. The installer and uninstaller manage both together.

The project page reads GOALS.md, decision JSON, documents, notes, plans and changes. Claude transcript lookup derives the directory key from the configured project root; no transcript is invented when absent. Long replies are exported to `docs/changes/chat/`. Board messages and `ray note` are durable notes; this portable kit does not install a Claude messaging hook or promise live delivery. The agent reads notes when it resumes. Stats uses local transcript, keeper-log and retained check records; missing records produce no measurements. Cost is a list-price estimate, not a bill. Optional usage proxy reads only the configured local database; absent or incompatible data hides the section.

The sharing API publishes the reviewed RPM and explicitly allowlisted files and decisions. Invitation hashes live under the project `.board/` directory; remote connection credentials live in the managed settings directory. See the Guide for access control and transport. The starter retains the Markdown outcome Check and the original static-site/check workflow; it does not run arbitrary outcome commands from the new project board. Machine-specific agent automation, private fleet ledger and workspace integrations, benchmark fixtures, and external desktop renderers are not bundled. Guest handoff metadata requires a ledger integration and is empty in this starter; reviewed handoff material can be published as a document.
